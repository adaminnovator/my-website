Device Log Export & Collection Guide

For R&D Engineer Analysis

When any issue or abnormal behavior happen on the device, collect the following information for R&D analysis:

1. Required Information Collection

  1. FW version number.
  2. Configuration file (The issue may related with config, please export to us).
  3. Export the operation log and alarm log (Cover the issue happen time).
  4. Download the right time print log:

    Help engineers know internal device status

    Access path: Input "IP/logs" in browser

    Log example: lg26031301x.gz (Hour log: 2026.03.13 13:00:00--2026.03.13 14:00:00)

    Ensure the issue happen during this one hour time.

  5. The issue phenomenon record

2. Issue Phenomenon Record Requirements

  • Record a short video or take pictures to show the issue phenomenon.
  • Confirm the issue happen frequency.
  • Check if only this device has the issue.
  • Verify if the same operation can reproduce the issue every time.

3. Usage Examples

Example No.1

When a device encounters an anomaly during liveview or playback:

1. Check video live view&playback through a browser.

2. View original video using CB2/Local player.

3. Pinpoint if the original recording file is faulty.

4. Share the faulty exported video for analysis.

Example No.2

When encountering abnormal device startup times:

1. Confirm if only this specific device has the problem.

2. Same firmware devices do not exhibit the issue → likely hardware/power supply malfunction.

3. Capture restart process video with mobile phone.

4. Export print log after device boots up successfully.
