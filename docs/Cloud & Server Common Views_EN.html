Cloud & Server Common Views

Adaptation Descriptions

Customer-hosted, dedicated FT-Cloud deployment environment for a customer. Due to regulatory, security, and internal audit requirements, some common views below before proceeding.

1. Data path and routing (critical requirement)

All video, audio, and metadata generated by DVR devices must be transmitted directly from the vehicles to the customer-hosted FT-Cloud servers.

No video, audio, or metadata may be:

  • routed via,
  • mirrored to, or
  • temporarily stored on any Streamax-operated or third-party servers.

The required data path must be:

DVR → customer-owned infrastructure → customer-owned storage

2. No external access to video data

Streamax and its subcontractors must not have direct or indirect access to:

  • live video streams
  • recorded video files
  • audio recordings
  • video exports or playback

This applies at all times, including during:

  • technical support
  • troubleshooting
  • upgrades
  • incident handling

Common views:

After "Local Server" set up, it is possible. However, if you requires Streamax to support in any matters, such as technical support or upgrades, technically, you could share the authorization of the access to the server, and we may be assist you only under your requirements.

3. Customer-owned infrastructure

The dedicated FT-Cloud instance must be deployed and operated in:

  • the customer’s own data center or - Yes, physical computer
  • the customer’s own cloud project (e.g. Google Cloud, Azure, AWS) - Recommend

be fully under the customer’s control regarding: - Yes

  • network configuration
  • firewall rules
  • routing policies

The customer must be able to technically verify that no outbound traffic to Streamax IP ranges is required for media or metadata transmission. - No

4. No hidden or automatic data transmission - No

The FT-Cloud solution must not include: - No, not include

  • hidden data transfers
  • background mirroring
  • undocumented synchronization
  • telemetry containing video, image, audio, or vehicle-related metadata to Streamax or any third party

Any license validation or system health communication must be:

  • documented
  • configurable
  • free of customer data

5. Access control and accounts - Yes

All user accounts, roles, and permissions must be created and managed exclusively by the customer.

Streamax must not have: - No

  • permanent administrator accounts
  • predefined support accounts
  • backdoor or emergency access

If temporary support access is required, it must: - Yes

  • be initiated by the customer
  • be time-limited
  • be fully logged
  • be revocable immediately by the customer

6. Updates and maintenance

  • No automatic updates or changes may be applied without customer approval.
  • Updates must not:
    1. introduce new external network dependencies
    2. alter the video data path

Common views:

No, only under permission if really needed.

7. Audit and verification

The customer must be able to:

  • verify the data path via network logs
  • perform internal or third-party audits
  • technically demonstrate that:
    1. no video data leaves the customer environment
    2. no external media endpoints are used

Common views:

Access to your client's server is managed by your client, so in theory, it is your client themselves who should query and review these matters.
